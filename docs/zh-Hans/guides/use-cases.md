Monad 适合那些能从持久状态、明确职责，以及多种观察与执行方式中获益的工作。运行时本身是域中立的：会话、Agent、工具、审批和产物都不假设工作的类型，Workplace Experience 会把 Web 界面适配到你实际运行的领域。下面几节是例子，不是固定清单。

## 研究

Monad 支持研究工作的方式，是把每一条探索线索放进它自己的持久会话，并把支撑结论的资料作为产物保留下来，而不是让它们在对话记录里被滚动淹没。

把资料收集、综合和复核拆成边界清晰的工作线程。把报告和资料集合保留为产物，用不同成员做独立分析，让证据来源和它支撑的决定保持连接。

## 运维

Monad 支持运维工作的方式，是让一次事件的记录在消息渠道、浏览器和终端之间保持连续，同时让影响主机的工具停在审批边界上。

把运行手册、被监控的渠道、需审批的工具和持久的事件会话组合起来。即使操作者从消息渠道切换到 Web 界面或终端，守护进程仍提供一份连续记录。

## 内容生产

Monad 支持内容工作的方式，是给每个阶段——调研、起草、编辑、发布前检查——一个明确的负责人，同时任务、审批和产物仍归守护进程所有，并可从任何客户端访问。

把调研、起草、编辑和发布检查分配给明确的角色。Workplace Experience 可以组织 Web 端的工作流，而底层的任务、审批和产物依然归守护进程所有，也依然能被其他客户端访问。

## 软件开发

Monad 支持软件工作的方式，是把项目变成一个仓库的持久环境，让多个 Agent 运行时在同一套审批策略和同一条审计链下在其中工作。

把项目用作持久的仓库环境。以第三方 Agent 的形式运行服务商原生 Agent，把设计和复核工作放在不同会话里，对影响主机的操作要求审批，并从 Web 或 CLI 检视同一份活动记录。

## 个人 Agent 工作区

在你还没有团队的时候，Monad 就已经有用：一个人也能从同一个运行时获得持久会话、本地优先的状态、模型选择、技能、记忆和可替换的客户端。

一个人不必组建大团队也能使用 Monad。在加入第二个 Agent 之前，这些能力就已经有价值。

对于用完即弃、不需要恢复、不需要策略、不需要协作也不需要跨客户端的一次性提示，Monad 的价值不大。用与实际工作相称的最简单工具。
