Monad Mesh 持有团队身份、会话绑定、观察和策略。mesh 的每个成员由一个 Agent 运行时实际执行其轮次。按照"工作应该在哪里执行"和"你需要哪种服务商行为"来选择这个运行时——无论选哪个，成员的身份和历史都留在 mesh 里。

## Monad Agent Runtime（第一方）

当你想要最简单的配置、Monad 原生的工具与记忆、一致的审批行为和直接的模型服务商配置时，用 Monad 随附的 Agent 运行时。它是通用对话、研究、运维和工具驱动工作的默认成员——而且它是可选的：一个 mesh 可以完全由下面几种运行时组成。

## 第三方 Agent

当 Codex、Claude Code 这类服务商原生运行时应当在持久的 Monad 会话中执行时，用第三方 Agent。服务商保留自己的模型循环、认证、服务商会话和特有行为；Monad 提供项目成员身份、会话绑定、观察、协作和恢复。

当工作能从服务商自带的执行环境（它自己的工具、提示词和会话行为）中获益时，选这一种。

## Agent Client Protocol

ACP 可以双向使用：

- 把 Monad 作为 Agent 运行在兼容 ACP 的编辑器里。
- 让 Monad 把一个边界清晰的子任务委派给另一个 ACP Agent。

ACP 是协议桥，不是守护进程持久团队状态的替代品。当编辑器内的原生交互或协议级委派重要时，选它。

## 对等联邦

用对等联邦在同一操作者拥有的多个 Monad 守护进程之间委派工作。它适用于同一信任边界下的另一台机器或另一套环境，不建立跨所有者的身份、信任或计费关系。

## 决策表

| 需求 | 选择 |
|---|---|
| 最快跑通一个 mesh 成员 | Monad Agent Runtime |
| 服务商原生的执行行为 | 第三方 Agent |
| 编辑器集成或协议级委派 | ACP |
| 同一操作者拥有的另一台机器 | 对等联邦 |
| 相互独立的组织和信任域 | Monadix，而不是本地对等联邦 |

一个 mesh 可以同时使用多种方式。稳定的项目成员身份让成员底层的 Agent 运行时可以更换，而不会因此变成一个新的团队成员。
