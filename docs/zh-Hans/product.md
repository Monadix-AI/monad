Monad 是采用无头架构、以守护进程为核心的 Agent 团队运行时。它让团队持续在线、保存工作、执行策略，并允许人们通过不同客户端操作同一份状态。

## 产品核心是团队运行时

长期运行的 `monad` 守护进程是团队的权威来源。它独立于客户端和 Agent 运行时，负责身份、能力、权限、会话、协作状态、审批和审计历史。

这条边界带来四项产品特性：

- **连续性**：关闭客户端、重新连接或重启守护进程后，工作仍然存在
- **共享事实**：Agent 与人使用同一份持久化的工作和决策记录
- **可替换客户端**：Web、CLI、TUI、编辑器、API 和消息渠道控制同一份状态
- **受治理的自治**：能力、沙箱、观察和审批由运行时掌握

守护进程优先和无头描述的是产品行为，而不只是实现方式。客户端可以关闭或替换，但不会成为团队的所有者。

## Monad Mesh 是产品的首要能力

Monad Mesh 是守护进程对外提供的 Agent Team Runtime，负责持久成员身份、会话绑定、共享工作、观察、审批和恢复；底层权威仍属于 `monad` 守护进程。其他能力都以「它为 mesh 贡献了什么」来描述。

成员可以由任意 Agent 运行时承载：第三方 Agent 服务商运行时、Agent Client Protocol（ACP）Agent、你自己拥有的对等守护进程，或 Monad 的第一方运行时。它们保留各自服务商特有的执行行为，而团队成员、会话绑定、观察、策略和协作状态归 mesh 所有。

## Monad Agent Runtime 是第一方成员

Monad Agent Runtime 是 Monad 随附的第一方 Agent 运行时，也是 mesh 的默认成员，提供开箱即用的模型与工具循环、上下文管理、记忆、支持审批的工具执行和沙箱集成。

它是附加能力，不是产品边界：完全由第三方 Agent、ACP Agent 或对等守护进程组成的 mesh 同样成立。你可以从一个内置 Agent 开始，再加入其他运行时，无需把工作迁移到另一产品或数据孤岛。

## 客户端投射同一份状态

Web UI、命令行界面（CLI）、终端用户界面（TUI）、编辑器、API 和消息渠道都是守护进程的客户端。每种客户端可提供适合自身界面的控制方式，但跨客户端能力必须属于守护进程。

Workplace Experience 是守护进程所拥有的 Agent、任务、产物、审批和协作状态在 Web 端的投射。它可以针对编码、研究、运营或内容工作重组浏览器流程，但不能成为某项运行时能力唯一存在的地方。

## Monad 支持渐进式自治

人保留方向、判断与责任，Agent 在明确的能力和策略边界内执行工作。你可以先密切监督，再随着以下控制措施逐步授予更多自治权：

1. 为每个团队成员分配稳定身份和有限能力集
2. 在合适的沙箱中执行操作
3. 观察活动并保存结果
4. 对受控操作要求人工审批
5. 在中断或失败后恢复工作

## 产品边界保持明确

Monad 当前提供守护进程与 API 边界、持久会话、项目协作、外部运行时托管、ACP 委派、对等联合、审批门、活动记录和 Workplace Experience 扩展。

这些能力不代表任意分布式调度、通用任务与产物模式，或跨所有者的身份与信任。对等联合覆盖同一操作者拥有的机器；跨所有者协作属于 Monadix。

Monad 是本地优先，而非只能离线。Monad 拥有的状态默认留在你的设备上；发往所配置模型服务商的请求则遵循你选择的网络与凭据设置。
